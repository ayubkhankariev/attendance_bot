# TTPU Monitor — автоматическая проверка занятий по камерам

Программа делает то, что вы делаете вручную каждую пару:

1. Сама берёт расписание с https://ttpu.edupage.org/timetable/ (то же, что в TTPU.pdf).
2. Через 10 минут после начала каждой пары сама делает снимок с камеры нужной аудитории (те же камеры Hikvision, что вы смотрите в iVMS-4200 — программа обращается к ним напрямую, iVMS открывать не нужно).
3. Считает людей на фото нейросетью (YOLO).
4. Формирует подпись в вашем формате:

   ```
   Web programming
   KH.KHAMIDULLA
   LAB 403
   AE1-24 / AE2-24
   ```

   Если студентов меньше 10 — добавляет `#TALABALARSONI 5/58`.
   Если аудитория пустая — добавляет `#DARSBARBOD`.
5. Отправляет фото с подписью в Telegram-группу руководителей.

Есть два режима:

* **review (рекомендуется)** — бот сначала присылает фото **вам** с кнопками:
  ➖ / 👥 5 / ➕ — исправить число студентов (нейросеть может ошибаться),
  ✅ Отправить — опубликовать в группу руководителей,
  ⏭ Пропустить — не отправлять.
  Вместо 15–20 минут ручной работы каждую пару вы просто нажимаете 1–2 кнопки в телефоне.
* **auto** — бот отправляет в группу сразу без вашего участия. Включайте, когда убедитесь, что подсчёт работает точно.

## Установка (Windows, тот же компьютер, где стоит iVMS-4200, или любой ПК в той же сети)

### Шаг 1. Python

Установите Python 3.10+ с https://www.python.org/downloads/ (при установке отметьте галочку **"Add Python to PATH"**).

### Шаг 2. Скачайте проект и установите зависимости

Распакуйте папку `ttpu-monitor`, откройте в ней командную строку (Shift+ПКМ → «Открыть окно PowerShell здесь») и выполните:

```
pip install -r requirements.txt
```

Первая установка займёт время (~2 ГБ, скачивается нейросеть PyTorch). Если интернет слабый — можно временно поставить в config `counting: enabled: false` и установить только лёгкую часть:

```
pip install "python-telegram-bot[job-queue]" requests PyYAML pytz
```

### Шаг 3. Создайте Telegram-бота

1. В Telegram напишите боту **@BotFather** → `/newbot` → придумайте имя → получите **токен** вида `1234567890:AAE...`.
2. Добавьте бота в группу руководителей и сделайте его администратором (иначе он не сможет отправлять фото).

### Шаг 4. Настройте config.yaml

Скопируйте `config.example.yaml` → `config.yaml` и заполните:

* `bot_token` — токен из шага 3.
* Запустите бота командой `python -m monitor.main`, затем:
  * напишите **в группе руководителей** команду `/id` — бот ответит ID группы → впишите в `target_chat_id`;
  * напишите боту **в личку** `/id` → впишите в `review_chat_id`.
* `group_sizes` — сколько студентов числится в каждой группе (для записи 5/58).

### Шаг 5. Камеры

Для каждой аудитории нужен адрес снимка. IP-адреса камер и регистраторов смотрите в **iVMS-4200 → Device Management → Device** (колонка IP).

* Камера подключена напрямую:
  `http://IP_КАМЕРЫ/ISAPI/Streaming/channels/101/picture`
* Камеры подключены через регистратор (NVR) — канал N:
  `http://IP_РЕГИСТРАТОРА/ISAPI/Streaming/channels/N01/picture`
  (канал 4 → `401`, канал 12 → `1201`)
* Проверить адрес легко: вставьте его в браузер — должен открыться снимок (браузер спросит логин/пароль камеры).
* Если ISAPI отключён, используйте RTSP:
  `rtsp://логин:пароль@IP:554/Streaming/Channels/101`

Ключ камеры в конфиге = название аудитории **точно как в расписании EduPage** (`LAB 406`, `203`, `201`...). Проверить названия: `python -m monitor.main --print-timetable`.

### Шаг 6. Проверка перед запуском

```
python -m monitor.main --print-timetable          # расписание на сегодня + для каких аудиторий есть камеры
python -m monitor.main --print-timetable 2026-07-09   # на конкретную дату
python -m monitor.main --test-camera "LAB 406"    # снимок с камеры + подсчёт людей (сохранит 2 файла jpg)
```

### Шаг 7. Запуск

```
python -m monitor.main
```

Бот работает, пока открыто окно. Проверки запускаются автоматически: 9:10, 10:40, 12:10, 14:30, 16:00, 17:30, 19:00, 20:30 (начало пары + 10 минут, настраивается) по рабочим дням Пн–Сб.

Команды бота (пишите ему в личку):

| Команда | Что делает |
|---|---|
| `/plan` | план проверок на сегодня |
| `/check 2` | проверить 2-ю пару прямо сейчас (удобно для теста) |
| `/rooms` | список настроенных камер |
| `/id` | ID чата |

### Шаг 8. Автозапуск (чтобы работало само каждый день)

Windows → «Планировщик заданий» (Task Scheduler) → Создать задачу:
* Триггер: «При входе в систему» (или ежедневно в 08:00);
* Действие: программа `python`, аргументы `-m monitor.main`, рабочая папка — папка проекта;
* В свойствах: «Выполнять, даже если пользователь не вошёл в систему».

## Важные замечания

* **Точность подсчёта.** Нейросеть считает людей на фото очень неплохо, но в заполненной аудитории с перекрытиями может ошибаться на 1–3 человека. Поэтому первые недели используйте режим `review` — вы видите фото с нарисованными рамками вокруг найденных людей и одним нажатием ➕/➖ исправляете число. Ошибки чаще всего при мелких/перекрытых фигурах; порог можно подстроить (`counting.confidence`: меньше — находит больше, но больше ложных).
* **Преподаватель.** Автоматически надёжно отличить преподавателя от студента нельзя, поэтому по умолчанию (`assume_teacher_in_count: true`) считается: студенты = найдено людей − 1. Если преподавателя нет — поправьте число кнопкой в режиме review. `#DARSBARBOD` ставится, когда на фото вообще никого нет.
* **Аудитории без камер** (Grey Hall, Online, Blue Hall и т.п.) просто пропускаются — утренний план (`/plan`) показывает, что будет проверено, а что нет.
* **Если EduPage изменит формат данных**, бот напишет об этом в ваш чат — тогда парсер (`monitor/timetable.py`) нужно будет чуть обновить.
* Компьютер с ботом должен быть **в одной сети с камерами** и иметь доступ в интернет (Telegram + EduPage).

## Структура проекта

```
ttpu-monitor/
├── config.example.yaml    ← скопировать в config.yaml и заполнить
├── requirements.txt
├── README.md
└── monitor/
    ├── main.py            ← бот, планировщик, кнопки, CLI
    ├── timetable.py       ← расписание с EduPage
    ├── camera.py          ← снимки с камер Hikvision (ISAPI/RTSP)
    ├── people_counter.py  ← подсчёт людей (YOLO)
    └── config.py          ← чтение config.yaml
```
